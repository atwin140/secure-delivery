# External prerequisites and validation checklist

This is the single checklist of environment-dependent work. Building, local testing, and an isolated ACM deployment test were authorized; production rollout and live email were not. Completed test-environment evidence is in [cluster-test.md](cluster-test.md). Mark each item with date, operator and an evidence artifact from the intended environment.

| Item                               | Required action and evidence                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Explicit environment authorization | Identify the nonproduction/production namespace, DNS name, owner and permitted email test recipients before applying manifests or sending mail.                                                                                                                                                                                                                                                                                                        |
| Supported runtime/images           | Build both pinned Containerfiles in a functioning container engine; scan images, generate image-layer SBOMs and record application/database image digests. The host Podman engines still refused connections. Both application Containerfiles were built successfully with OpenShift Buildah and deployed by digest in the isolated ACM namespace. Image-layer scanning remains to be recorded.                                                        |
| Namespace and block storage        | One tenant/namespace; verify restricted SCC admits arbitrary namespace UIDs with no privilege escalation, writable-volume permissions, PVC binding and resource limits. Confirm single Postgres availability/maintenance expectations; no HA claim.                                                                                                                                                                                                    |
| Public configuration               | Copy `deploy/operator.example.json` to an operator-controlled nonsecret file. Supply exact hostname, immutable built-image digests, OIDC/Graph settings, provisioning **S3 storage class**, bucket, block class and approved egress CIDRs. Supply service/external CA PEM files. No crypto overrides.                                                                                                                                                  |
| Secrets                            | Provision only the named Secret contracts from `deploy/secrets.example.yaml` through the approved secret manager. Use separate app/admin/backup database credentials as described; no populated files in this repository. Configure rotation ownership and expiry alerts.                                                                                                                                                                              |
| TLS/DNS                            | Verify browser→router, re-encrypt router→app, app→Postgres, app→S3, Keycloak, Entra and Graph certificate chains and hostname validation. Use service FQDNs matching SANs. Provision cert-manager public/internal issuers and obtain the internal CA before rendering the Route destination CA. Configure exact API egress CIDRs and monitor certificate/reload Job failures; see cert-manager.md. Test bad CA/hostname rejection in the actual stack. |
| Network isolation                  | Validate default deny and allowed DNS/router/database/monitoring paths. Supply approved CIDRs for S3, Keycloak, Entra and Graph; standard NetworkPolicy has no FQDN rules. Use the platform egress gateway/firewall/proxy to maintain changing provider IP ranges; avoid global `0.0.0.0/0` allowances. Verify denied egress and namespace isolation with live probes.                                                                                 |
| Keycloak                           | Exact callback/origin, confidential client, PKCE S256, required client role and access-token audience mapper. Verify allowed sender, missing role, wrong audience/issuer and cross-owner denial against the real realm.                                                                                                                                                                                                                                |
| ODF/S3 compatibility               | Run application preflight. Obtain gateway version and capability results. Inspect OBC, BucketClass, BackingStore and NamespaceStore for replicationPolicy/sync_versions and backing-store retention. Inspect all object versions, delete markers and multipart uploads. Unsupported/unprovable required APIs are a concrete compatibility blocker.                                                                                                     |
| Storage deletion policy            | Exclude the document bucket from all backups, snapshots, retained versions, object locks and replication that preserves deleted versions. Confirm provider garbage-collection/deletion semantics and prove absence within 24h under an injected cleanup outage. S3 HEAD alone does not establish underlying physical erasure.                                                                                                                          |
| Graph mailbox scope                | Dedicated mailbox. Exchange Application RBAC `Application Mail.Send` with a resource scope restricted to that mailbox. Audit/remove additive Entra application Mail.Send grants that bypass the scope. Run `Test-ServicePrincipalAuthorization` for both allowed and denied mailboxes, plus a separate Entra-grant review. Retain evidence of effective scope.                                                                                         |
| Live mail (authorized only)        | Verify exact generic body/link/expiry, BCC handling, no bundle/password/internal metadata, `saveToSentItems=false`, explicit retry after rejection and absence of persisted recipient addresses. Test an out-of-scope mailbox is denied. Document provider retention and that acceptance is not delivery.                                                                                                                                              |
| Migrations and retrieval gate      | Apply rendered manifests with retrieval false. Run migration inside configured application image, then preflight. Set ConfigMap retrieval true and run `enable-retrieval` only after environment checks. Confirm initial switches and safe restore cannot expose old data.                                                                                                                                                                             |
| Active streams across replicas     | Start slow transfers through multiple pods, revoke/expire/reissue, disrupt database/listener/S3 and cancel clients. Measure stop latency, socket bytes already in flight and recovery behavior. Do not claim instantaneous recall.                                                                                                                                                                                                                     |
| Logging/canary audit               | Use synthetic plaintext, filenames, passwords and key bytes. Inspect app/ingress/WAF/APM/Postgres/ODF/provider error logs, request traces, database tables and stored objects. Ensure capabilities are absent from request URLs/logs and bundle/key/password/internal metadata never reaches application APIs. Disable unwanted body/header/SQL-parameter logging.                                                                                     |
| Backup/restore drill               | Daily backups retained 30 days on protected metadata-only storage. Measure actual pg_dump/pg_restore/RTO and verify up-to-24h RPO. Restore with app scaled down, invalidate every recovered delivery, reconcile all ciphertext and prove revoked deliveries cannot reappear. Record audit history lost since backup.                                                                                                                                   |
| Cleanup/backup monitoring          | Install/adapt optional monitoring resources, route alerts, inject deletion failure and missed backup. Prove oldest pending cleanup warns at 23h and absence is established by 24h. Retain deletion/alert evidence.                                                                                                                                                                                                                                     |
| Browser support                    | Repeat normal-profile Chrome and Edge tests on actual supported hardware/OS. Benchmark unlock and full-size individual/ZIP output to native filesystem destinations. A private Chrome context failed at 1 GiB; do not claim that environment supported. Native Save dialogs could not be controlled by the local UI bridge; verify them manually with the supplied script.                                                                             |
| Compatibility and accessibility    | Measure Firefox/Safari separately; unsupported-feature screen is implemented but compatibility is not declared. Manual keyboard-only workflow, screen reader announcements/focus, 200% zoom, reflow, contrast and native dialogs supplement automated WCAG checks.                                                                                                                                                                                     |
| Operational acceptance             | Review threat boundaries, dependency/image reports, configured retention and restoration evidence. Obtain accountable owner acceptance. No mandatory independent security-review release gate is imposed by this implementation, and no audit/certification is claimed.                                                                                                                                                                                |
