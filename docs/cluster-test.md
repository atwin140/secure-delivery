The namespace contains the two-replica app, one PostgreSQL instance, one separate TLS Keycloak instance, a private authenticated TLS image registry, a dedicated RGW ObjectBucketClaim, three 10 GiB block PVCs (database, metadata backups and registry), and completed build/test Jobs. ## Failures found and corrected

1. The first two build pods were evicted by low worker disk space. Retried on `acm-wk-03` after checking filesystem capacity; no existing data was removed.
2. The workstation resolved the public ingress address while cluster DNS resolved `10.0.1.21`. Added the actual internal HTTPS destination to the precise test egress policy.
3. RGW reports absent bucket replication as an empty Role with no Rules. Updated the parser to accept only a semantically empty envelope; negative tests still reject rules, roles and uncertain responses.
4. A readiness check through the Service could not reach unready replicas. It now connects to the same replica through loopback while retaining the service hostname for certificate verification/SNI.
5. The synthetic Keycloak realm omitted the `basic` scope and therefore access-token `sub`. Corrected it through supported offline realm import; the app's subject requirement was retained. The synthetic profile data also includes a non-deliverable test email.
6. The cluster browser harness originally read the generated bundle password before crypto initialization finished. Added the same readiness wait used by the local test. Product crypto was unchanged.

## Evidence and repeatability

`evidence/cluster-test/` contains curated build and Job states, admitted runtime security settings, the browser result, final Route checks, restore/provider checks, public rendered manifests and a 4K screenshot. Reports omit credentials, tokens, capabilities and provider error objects. The obsolete system Python trust store failed an HTTPS check; final checks used the supported Node 24 default trust store with certificate verification enabled.

The `scripts/cluster-test-*.mjs` and `.ts` files document the explicit test orchestration. They require `KUBECONFIG` and target only this namespace. `cluster-test-restore.mjs` intentionally replaces the synthetic delivery database after stopping the app; it must be followed by `restore-invalidate`, cleanup, validation and deliberate re-enablement. Do not run it against real data. Test Secrets are generated in memory and stored in Kubernetes, never in image build context or local source. The normal `scripts/render.mjs` and `scripts/deploy.sh` remain the operator deployment entrypoints.
